# BLACKOUT 게임성 evals · 5회 개선 루프

2026-09-18 사용자 요청으로 기본 게임을 게임성 개선 전 `checkpoints/r00` (`624f50f`)으로 롤백했다. [롤백 기록](ROLLBACK-2026-09-18.md)을 확인한다. [V2 루프](v2-loop.md)와 아래 설계는 이전 실험 기록으로 보존하며, 현재 게임 규칙의 통과 기준으로 적용하지 않는다.

이 문서는 **개선 전 설계 계약**이다. 2026-09-17 기준선을 바탕으로 작성했으며, 후속 사용자 요청에 따라 구현자와 별도 평가 작업을 분리해 실행하고 있다. 실제 회차별 판정과 수정 이력은 [LOOP.md](LOOP.md)를 확인한다. 아래 인간 플레이 목표는 아직 검증 결과가 아니다. 기존 작업은 `checkpoints/r00`에 보존했다.

## 1. 개선할 경험

목표는 **“불을 켰다 → 새 수요 때문에 선택한다 → 위험을 읽는다 → 내 설계로 복구한다 → 다른 설계도 해보고 싶다”**이다. 핵심 성공 지표는 플레이어가 이유를 설명할 수 있는 재설계와 자발적 재도전이다. 클릭 수·효과 수·접속 시간 증가는 그 자체로 성공이 아니다.

원본의 5분 플레이, 직접 배선, 현상에서 발견하는 학습, 무료 수정, 게임오버 없는 회복을 유지한다. 아래의 케이블 보유량은 전략 실험을 위한 **새 규칙 후보**다. 기존 기획의 무비용 수정 원칙과 구별해, 철거 시 전량 회수하고 수정 벌점은 부과하지 않는다. 도입 여부는 3회차에서 검증한다.

### 개선 전 기준선 코드에서 확인한 것

| 근거 | 현재 동작 | 검증할 게임성 가설 |
| --- | --- | --- |
| `game.js:loadPlan`, `update` | 시설 0 / 30 / 90 / 225초, 전류계 65초, 분기 90초 해금 | 숙련자는 다음 사건을 기다리고, 초보자는 필요한 도구가 잠겨 있을 수 있다. 90→225초 간격은 135초지만 실제 무행동 시간은 아직 미측정이다. |
| `engine.js:analyze` | 네 시설에 독립 공급·귀환선을 만들면 안정화 가능 | 같은 배선을 반복하는 해법이 충분해 재설계 선택이 약할 수 있다. 실제 사용 비중은 미측정이다. |
| `game.js:update`, `engine.js:tickHeat` | 과부하 6초 후 단선, 안전하면 냉각, 전체 안정 8초 후 승리 | 실패를 원인 이해와 복구로 연결하는지가 중요하다. 단선 횟수를 높이는 것이 목표가 아니다. |
| `game.js:win`, 결과 화면 | 복구 시간·도시 점등·회로도·재시작 | 첫 완료의 만족과 두 번째 플레이의 다른 선택을 각각 검증할 필요가 있다. |

`baseline.cjs`는 실제 엔진으로 열린 회로, 직렬, 독립 병렬, 공용 간선 과부하를 재현한다. `baseline.json`에는 소스 SHA-256과 측정값을 남긴다. **고정 회로 진단**이므로 입력 품질·진행 시간·재미·플레이어 전략 분포는 평가하지 않는다.

이번 진단 결과: 독립 8선은 전체 안정, 시설 밝기 약 0.970~0.971. 공용 간선은 약 1.323A로 공급·귀환 양쪽에서 과부하가 나며 6초에 단선됐다. 기존 Node 테스트 45개와 문법 검사를 통과했다. 브라우저 통합 및 사람 플레이테스트는 이번 설계 작업에서 실행하지 않았다.

## 2. 평가를 세 층으로 분리한다

| 층 | 평가 방식 | 판정 |
| --- | --- | --- |
| A. 규칙과 회귀 | 기존 Node 테스트 + 결정적 시나리오 + 브라우저 통합 | 필수 항목 100% 통과. 하나라도 실패하면 후보 채택 금지. |
| B. 플레이 가능성 | 실제 포인터·터치·키보드, 시간 흐름, 고정 시나리오와 전략 재생 | 모든 시나리오에 완료 가능한 해법, 입력 불능·진행 교착 0건. |
| C. 재미와 이해 | 대상 학습자 관찰, 행동 로그, 짧은 사후 질문 | 회차별 주지표 목표 + 다른 경험 악화 여부로 채택 / 보류 / 기각. |

자동 테스트 통과를 C층 통과로 대체하지 않는다. 종합 점수로 치명적 결함을 평균내지 않는다. LLM은 로그에서 문제 후보와 질문을 정리할 수 있지만, 자기가 만든 변경의 재미를 최종 채점하지 않는다.

| ID | 준비와 행동 | 기대 결과 / 판정 |

## 3. 계측 계약

1회차 기능 변경 전에 최소 수집기를 붙이고 현재 버전의 사람 기준선을 확보한다. 이벤트는 로컬 메모리/JSON 내보내기로 충분하다. 이름 등 개인정보 대신 익명 세션 ID를 쓴다. 매 프레임 DOM을 저장하지 않는다.

공통 필드: `schemaVersion, runId, buildHash, variant, scenarioId, seed, inputMode, eventSeq, wallMs, activeMs, event, payload`. `activeMs`는 시작 후 실제 진행 시간이며 도움말·일시정지·백그라운드는 제외한다. `wallMs`는 세션 시작 기준 단조 증가 시간이다. 사람 지표에는 `advance()`로 가속한 런을 넣지 않는다.

| 이벤트 | 데이터와 발생 기준 | 연결할 위치 |
| --- | --- | --- |
| `run_start`, `run_end` | 첫 시작 / 승리·재시작·종료. 종료 미관측은 censored 표기 | `start`, `win`, 재시작, 명시적 종료 |
| `connect_attempt`, `connect_result` | 단자, 입력 방식, 성공·중복·미스·취소 사유. 놓침도 포함 | pointer / keyboard 입력 경계 + `addConnection`, `addBranch` |
| `wire_removed`, `branch_created` | 관련 ID, 자발적 수정인지 단선인지, 전후 그래프 hash | `removeWire`, `addBranch` |
| `facility_spawn`, `tool_unlock` | 발생 원인과 진행 단계 | `update` / 차후 director |
| `facility_state` | off / dim / stable 전이, 밝기·전류. 0.25초 지속 후 확정 | `analyze` 결과 전이 감시 |
| `overload_start`, `overload_end`, `wire_break` | wire ID, 전류, 용량, heat, 같은 episode ID | `update`, `tickHeat` 전후 |
| `measure`, `help_open`, `pause`, `resume` | 대상 전선·수치 / 이유 | `measure`, `showHelp`, `pause` |
| `result_shown`, `replay_start` | 감상 종료와 재도전 시작, 다음 시나리오 | 결과 표시, `replay` |
| `sample` | 1초마다 시설 상태 수, 최대 열, 현재 수요, 수정 가능 여부 | 진행 tick |

각 회차에서 계측 신뢰성도 확인한다: 두 전선 첫 점등 1회, 잠시 꺼졌다 켜져도 first light 중복 없음, 과부하 해소 후 새 과부하는 새 episode, 실패한 분기에는 성공 이벤트 없음, 동일 결과 표시 프레임마다 로그가 쌓이지 않음.

### 지표 정의와 초기 목표

다음 수치는 **이 프로젝트의 실험용 가설 목표**이며 업계 기준이나 현재 측정 결과가 아니다. 후보를 실행하기 전에 고정하며 결과를 본 뒤 유리하게 바꾸지 않는다. 각 비율에 분자/분모, 시간에 표본 수·중앙값·범위를 붙인다.

| 지표 | 정의 | 초기 목표 |
| --- | --- | --- |
| 첫 점등 | `run_start`→첫 주택 stable 전이의 active 초. 미완료도 별도 실패 수에 포함 | 신규 8명 중 ≥6명이 30초 내, 완료자 중앙값 ≤20초 |
| 배선 미스율 | 의도한 연결 시도 중 놓침/무효 비율. 명시적 Esc 취소와 의도적 전기 실험은 별도 | ≤15%, 입력 방식별 보고 |
| 강제 대기 | 등장 시설 모두 안정 + 진행 가능한 현재 과제 없음 + 다음 사건 미발생인 연속 시간 | 8초 안정화 연출을 제외한 최대 구간 ≤15초 |
| 체감 공백 | 20초 이상 의미 행동이 없는 구간을 관찰자가 관찰/고민/대기/길 잃음으로 분류 | 대기 또는 길 잃음 합계가 기준선 대비 ≥30% 감소 |
| 의미 있는 재설계 | 문제 관찰→배선 변경→상태 회복/열 완화가 15초 안에 이어지고, 사후에 변경 이유를 설명 | 고정 문제 시나리오 8명 중 ≥5명에서 1회 이상 |
| 위기 복구 | 첫 단선→당시 등장 시설 전체 안정. 회복 전 새 등장 억제. 45초 초과·중단도 실패로 기록 | 위기 노출 8명 중 ≥6명 45초 내 복구 |
| 전략 분포 | 최종 시설의 공유 공급/귀환 구조로 독립형·공유형·혼합형 분류. 좌표 차이는 같은 전략 | 세 시나리오에서 유효 해법 2종 이상. 사람 표본의 최빈 전략 >75%는 진단 신호 |
| 원인 이해 | “왜 어두워졌고/끊어졌고, 무엇을 바꿨나요?”에 현상과 행동 인과를 설명 | 고정 위기 시나리오 8명 중 ≥6명 |
| 런 완료 | 300 active 초 내 승리 수 / 시작한 정상 세션 수. 중도 이탈 포함 | ≥6/8, 영구 진행 불능 0 |
| 재도전 | 결과를 본 뒤 60 wall 초 안에 독촉 없이 재시작. 기회가 제공된 완료자만 분모 | ≥50%, 완료율과 함께 보고 |
| 재미 자기보고 | 종료 후 “다시 해보고 싶은 정도” 1~5 및 한 문장 이유 | 중앙값 ≥4; 행동 재도전과 따로 표시 |

‘측정 도구 사용 횟수’는 보조 지표다. 올바르게 이해한 플레이어가 도구 없이 해결해도 성공이다. 실패 횟수, 총 조작량, 긴 플레이 시간을 최대화하지 않는다.

## 4. 정확히 5회의 개선 실험

기준선 확보는 준비 단계이며 개선 횟수에 포함하지 않는다. 각 회차는 **하나의 변경 묶음·주가설·주지표**만 가진다. 후보를 기각해도 한 회차를 사용한 것으로 기록한다. 다섯 번을 모두 성공했다고 만들지 않는다.

| 회차 | 가설과 변경 후보 | 주지표 · 채택 목표 | 회귀 / 중단 조건 |
| --- | --- | --- | --- |
| 1. 연결의 손맛 | 귀환선까지의 짧은 시각 안내, 유효 단자 스냅과 놓침 피드백을 하나의 첫 연결 개선으로 묶는다. 첫 점등 순간 주변 도시 반응을 명확히 한다. | 신규 8명 중 ≥6명 30초 내 점등, 완료자 중앙값 ≤20초. 이미 달성하면 배선 미스율 20% 상대 감소를 사전 주지표로 선택. | 터치/키보드 사용 불가, 전기적으로 틀린 회로 점등, 안내가 조작을 가리면 기각. |
| 2. 플레이의 리듬 | `loadPlan.at` 중심에서 이전 시설 안정과 경과 시간을 함께 보는 director로 전환. 빠른 사람은 조기 등장, 느린 사람은 도움과 복구 기회. | 강제 대기 최대 ≤15초, 체감 공백 ≥30% 감소. | 신규 완료율이 기준선보다 2/8명 이상 하락하거나 복구 중 사건이 겹치면 기각. |
| 3. 설계의 선택 | 케이블 보유량/재사용 한 규칙을 실험. 독립선의 안정성과 짧은 공유선의 효율 사이에 선택을 만든다. 철거 시 100% 회수. | 8명 중 ≥5명 의미 있는 재설계. 고정 세 시나리오 각각 완료 가능한 서로 다른 배선 해법 ≥2개. | 자원 소프트락, 분기로 자원 복제, 선 길이 반올림 악용, 한 정답 강요면 기각. |
| 4. 위기와 역전 | 기존 6초 열 규칙은 유지하고 위험 구간→원인→복구 피드백을 일관되게 만든다. 더 큰 처벌은 추가하지 않는다. | 고정 위기 노출 8명 중 ≥6명 45초 내 복구, 원인 이해 ≥6/8. | 경고가 가려짐, 복구 직후 재난 연속 발생, 실패시 재시작 필수면 기각. |
| 5. 완료와 재도전 | 도시 복구 연출과 자신이 만든 배선의 차이를 결과에서 연결. 사전 검증한 다음 수요/배치 시드를 재도전에 제공. | 완료자 자발적 재도전 ≥50%, 자기보고 중앙값 ≥4, 전체 완료 ≥6/8. | 불가능한 시드, 첫 런 완료율 저하, 다음 판도 같은 행동 복사뿐이면 보류. |

### 회차별 구현 경계

**1회차:** `game.js` 입력·`connected`, `styles.css` 피드백. 전기 모델을 바꾸지 않는다. 물리적 실수와 회로 실험 실패를 나누어 기록한다. 안내 표시 여부 외에 난이도·시설 타이밍은 동결한다.

**2회차:** DOM 없는 `director.js` 후보를 분리한다. 입력 `{activeTime, stableSince, pendingDemand, recovering, stage}` → 출력 `{spawn, unlock, hint}`. 초안은 이전 단계 4초 안정 후 3초 예고, 신규 시설 최소 등장 간격 12초. 25초간 진전이 없으면 도움을 제공하고 다음 수요를 누적시키지 않는다. 전류계는 두 번째 시설 등장, 분기는 두 번째 시설 첫 점등 후 개방한다. 따라서 30초보다 빨리 도구가 필요하면 사용할 수 있다. 5분 초과 시 기존처럼 계속 복구 가능하다. 정확한 타이밍은 회차 시작 전 설정 파일에 고정한다.

**3회차:** 먼저 실제 `router.js` 경로 길이를 이용해 각 시나리오의 독립/공유/혼합 해법 길이를 계산한다. 케이블 단위는 world 좌표 길이로 고정하고 확대율과 무관하게 한다. 용량 0.75A와 전기 저항 모델은 그대로 유지한다. 예산은 임의 숫자로 정하지 않고 두 개 이상의 완료 해법이 들어오는 범위에서 고른다. 신규 수요와 함께 자원을 지급하고, 필요하면 철거·복구에 쓸 소량의 여유도 포함한다. 배선 전 남은 양/필요량을 짧게 보여준다. 자원이 재미보다 마찰을 늘리면 후보 전체를 기각하고 직전 채택 버전으로 복귀한다.

**4회차:** 자연 런에서 위기를 강제로 만들지 않는다. 동일한 공용 간선 과부하 직전 저장 상태를 양 버전에 제공해 복구 가능성을 비교하고, 별도로 자연 런의 위기 노출 빈도를 기록한다. 안전하게 설계한 사람에게 벌을 주지 않는다. 3회차가 기각됐어도 기존 회로 위기 상태로 이 실험을 진행할 수 있다.

**5회차:** 무제한 랜덤 대신 seed `101/202/303`의 검증된 세 수요·배치 조합으로 시작한다. 이 번호는 재현 식별자이지 현재 구현된 랜덤 기능이 아니다. 첫 런은 비교를 위해 고정하고 재도전에만 다른 조합을 쓴다. 점수/별점 대신 실제 배선과 복구 순간을 결과로 보여준다. 아직 구현하지 않은 변수는 seed가 있다고 가정해 평가하지 않는다.

## 5. 루프 엔지니어링

```text
현재 작업 트리 기준선 저장(기존 미커밋 변경 포함) + 이벤트 수집 검증 + 사람 기준선
  ↓
for round in 1..5:
  직전 채택 버전과 해당 회차 계약 읽기
  가설 / 변경 범위 / 지표 / 목표 / 고정 시나리오 / 중단 기준 확정
  격리된 후보에서 해당 변경 묶음만 구현
  A층 자동 회귀 → B층 브라우저·전략 재생
  실패하면 해당 후보 범위에서 최대 2회 수리 후 재검증
  계속 실패하면 REJECT → 직전 채택 버전 유지 → 다음 회차
  통과하면 C층 사람 테스트와 로그 검토
  증거 충족이면 ACCEPT, 악화면 REJECT, 불충분이면 HOLD
  결과와 증거·채택 버전·다음 가설 저장
  ↓
5회 결과표 + 최종 채택 버전 + 기준선 대비 변화 + 남은 미검증 항목
```

수리 횟수는 기능 실험을 추가하는 통로가 아니다. 새 가설은 다음 회차로 보낸다. `HOLD`는 채택이 아니며 다음 회차는 마지막 `ACCEPT`에서 시작한다. 사람 테스트가 불가능하면 자동 검증까지만 수행하고 `HOLD: human evidence missing`으로 남긴다. 후속 후보 설계는 가능하지만 재미 개선 완료로 보고하지 않는다.

### 비교·표본 운영

- 준비 및 각 회차에서 최소 8명의 대상 학습자로 방향성을 확인한다. 소표본 제품 판단이며 통계적 확증으로 표현하지 않는다. 한두 명 차이면 원자료를 검토하고 보류할 수 있다.
- 1회차 첫 점등은 학습 효과가 크므로 기준선 신규 8명과 후보 신규 8명을 비교한다. 동일인이 같은 문제를 두 번 풀어 빨라진 것을 개선으로 세지 않는다.
- 2~4회차는 가능하면 동일 8명이 기준선/후보를 모두 하되 순서를 AB 4명·BA 4명으로 나누고, 난도가 맞는 시나리오를 교차 배정한다. 적응 연습과 본 측정을 분리한다.
- 5회차 재도전은 첫 노출 경험이므로 기준선/후보에 신규 8명씩 배정한다. “다시 해보세요”라는 지시는 금지하고 양쪽 모두 동일한 60초 기회를 제공한다.
- 입력 방식과 숙련도를 기록하고 같은 장치끼리 비교한다. 터치·키보드는 별도 동작 확인도 수행한다. 실시간 해설을 요청하면 시간이 달라지므로 시간 측정 중에는 조용히 관찰하고 사후에 질문한다.
- 각 주지표 목표를 달성하고 비교 버전 대비 악화가 없어야 채택한다. 완료율 2/8명 이상 하락, 배선 미스율 +5%p, 혼란 평가 1점 이상 악화는 보류/기각 신호다. 필수 규칙 실패는 표본 크기와 관계없이 기각한다.
- 기준선이 이미 목표를 넘으면 시작 전에 더 민감한 개선 지표를 정한다. 사후 목표 변경은 새 실험으로 기록한다. 결측·중단을 성공 표본에서 조용히 제거하지 않는다.

### 구현 구조와 재현성

초기 구현 권장 분리: `director.js`(사건 순서), `run-config.js`(회차별 설정·시드), `telemetry.js`(이벤트 수집), 시나리오와 회차별 평가 자료. 실제 실행에서는 설정을 `runs.js`·`cable.js`로 나눴고, 평가자가 고정 시나리오·원자료·판정을 `evals/independent/`에 작성한다. 제품과 평가 코드의 작성 주체를 분리한 실제 경로는 [LOOP.md](LOOP.md)에 기록한다.

기존 `?test`의 `BlackoutTesting.snapshot/advance/connect/branch/remove`를 회귀용으로 활용하되, 결정적 eval 모드에서는 rAF 진행과 수동 `advance`가 시간을 이중 진행하지 않게 분리해야 한다. 입력 지연·손맛 평가는 가속 기능 없이 수행한다. 프레임별 렌더링과 규칙용 고정 시간 tick을 구분하고, 재생에는 실제 액션 시간도 기록한다.

전략 재생 정책은 독립 배선 / 공용 간선 / 혼합 분산 / 느린 초보 / 과부하 후 복구로 고정한다. 이는 물리·해결 가능성 탐색용이며 ‘AI가 이겼으니 재미있다’는 근거로 쓰지 않는다. 후보 조정에 쓰는 세 시나리오 외에 별도 세 배치(holdout)를 준비해 마지막에 확인하고, 실패하면 후보를 채택하지 않는다. 새로운 규칙의 자원 회계와 시드 해결 가능성은 해당 회차 구현에서 검증을 추가한다.

### 실행과 산출물

현재 바로 실행 가능한 명령:

```sh
npm test
npm run check
node evals/baseline.cjs
```

JSON 보존은 Node의 stdout을 UTF-8로 파일에 저장한다. 현재 `baseline.json`은 최초 기준선이므로 후속 출력은 다른 이름으로 보존한다. 브라우저 통합은 `npm start` 후 `http://127.0.0.1:4173/tests/browser.html`에서 실행한다. 기존 타이밍 테스트는 2회차에 기존 모드 보존 또는 새 계약으로의 의도적 변경을 명시해야 한다. 테스트를 삭제해 통과시키지 않는다.

`round-template.json`을 각 회차 폴더에 복사해 작성한다. 판정에는 최소 아래가 필요하다.

| 기록 | 필수 내용 |
| --- | --- |
| 버전 | 기준선/후보 hash, 미커밋 변경을 포함한 복원 가능한 스냅샷, 설정, 시드 |
| 증거 | 자동 실행 결과, 실제 입력 브라우저 기록, 익명 세션 로그와 관찰 메모 |
| 비교 | 주지표 분자/분모 또는 개별 시간, 기준선→후보 변화, 가드레일 |
| 판정 | ACCEPT / HOLD / REJECT, 반례, 미측정, 채택 버전 |
| 다음 단계 | 다음 회차 가설 한 문장과 범위. 다섯 번째 이후에는 잔여 과제로 남김 |

최종 보고는 `회차 | 가설 | 관측값 | 판정 | 채택 버전` 다섯 행으로 작성한다. 초기 설계의 `planned` 상태와 이후 실제 실행 상태를 혼동하지 않도록 [LOOP.md](LOOP.md)에 독립 판정을 기록한다. 자동 진단의 수치와 이후 실제 사람 관측값을 분리해 유지한다.

## 6. 다음 실행에 사용할 지시문

> evals/README.md의 5회 개선 계약을 따라 BLACKOUT을 개선한다. 먼저 기존 작업 변경을 포함한 복원 가능한 기준선을 저장하고 최소 이벤트 수집과 기준선 평가를 수행한다. 각 회차는 정해진 하나의 변경 묶음만 구현하며, 자동 회귀와 실제 브라우저 입력을 검증한 뒤 사람 플레이 증거로 채택 여부를 정한다. 결과는 round-template.json으로 기록한다. 실패 후보는 마지막 채택 버전으로 되돌리되 사용자의 기존 변경은 보존한다. 사람 테스트가 없으면 재미 검증을 HOLD로 남기고 수치나 평가를 꾸며내지 않는다. 정확히 5회 결과와 마지막 채택 버전, 미검증 항목을 보고한다.
