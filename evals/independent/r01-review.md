## 수정 요구

### R1-F01 / P2: 귀환선 먼저 연결하면 문구가 이미 연결한 선을 요구한다

재현: reset → start → lamp-1.right와 source.minus 연결. 강조는 source.plus와 lamp-1.left로 맞지만 상단 문구는 “1 / 2 연결 · 빛이 켜지려면 **돌아오는 길이 필요해요**.”다. 하단도 “돌아오는 길까지 이어 주세요.”로 표시된다. 실제 빠진 것은 공급선이다. R1의 명시적 필수 조건인 두 연결 순서 안내 정합성을 충족하지 않는다.

요구: 실제 빠진 극과 기기 단자에 맞춘 문구, 또는 두 순서 모두 참인 중립적 문구를 사용하고 상·하단을 일치시킨다. 해당 후보 `game.js:159` 및 `:190` 부근.

### R1-F02 / P2: dim 상태를 안정 점등 지표로 세는 계측 의미 불일치

재현: reset/start → advance(30.1) → source.plus→lamp-1.left → lamp-1.right→lamp-2.left → lamp-2.right→source.minus. 첫 주택 밝기는 **0.24880430621737198**, 안정 임계값 0.8 미만인데 `first_light`가 1회 기록되고 첫 연결 안내가 사라진다. `connected()`가 `powered`만 검사한다(`game.js:152`).

요구: 희미한 최초 발광과 계약상 첫 안정 점등을 구분한다. `first_light`를 안정 전이에 맞추거나 `first_powered`와 별도 `first_stable`/`facility_state`를 제공해 0.25초 확인 규칙을 적용한다. 안내를 숨길 시점은 별도 UX 판단으로 둘 수 있다. 평가상 핵심은 dim 상태를 안정 성공으로 계산하지 않는 것이다.

## 제한과 비차단 후속 사항

실제 터치, 작은 화면, 사람의 첫 점등·미스율·재미·이해도는 미실행이다. 키보드는 이번 후보의 기존 DOM 이벤트 통합 검사에 포함되고 기준선에서 네 단자의 실제 Enter 입력을 별도로 확인했다. rAF 시간 분리는 실시간 350ms 동안 0초 유지 후 advance(1) 정확히 1초로 검증했다.

최소 텔레메트리에는 buildHash/scenarioId/seed, 취소 결과, 전체 시설 상태와 episode 기록 등 README 전체 계약이 아직 없다. 외부 manifest로 이번 후보는 추적 가능하지만 후속 회차에서 지표를 계산하기 전에 필요한 필드를 완성해야 한다. 이번 REVISE는 위 두 구체 반례에 한정한다.
