# BLACKOUT — 전기적 제약과 전략 수정 중심의 재설계 계획

작성일: 2026-09-18. 사용자 피드백 7개를 반영한 **다음 구현 계획**이다. 이 문서 작성으로 제품 동작이 바뀌거나 새 평가가 통과한 것은 아니다. 이전 5회 실행과 판정은 [LOOP.md](LOOP.md)에 그대로 보존한다. 다음 구현에서는 이 계획이 기존 케이블 자원·자유 분기 계획을 대체한다.

후속 우선순위: 사용자가 현재 디자인과 연출을 유지하길 원한다. 따라서 도시·팔레트·점등·정전·완료 연출을 보존하고, 아래 화면 설계는 여백·선택 추적 등 조작 개선에 필요한 최소 변경으로 제한한다. 실제 구현과 독립 판정의 진행 상황은 [V2 실행 기록](v2-loop.md)에 남긴다. 중심은 새 화면이 아니라 전력 배분, 기존 배선 수리, 수요 변화에 대한 판단이다.

## 1. 바꿀 플레이 경험

**연결 → 상태 변화 관찰 → 문제가 생긴 회선 찾기 → 일부 연결을 삭제·이전 → 회복 → 바뀐 수요에 같은 판단 적용.**

목표는 전기 지식을 설명하게 만드는 것이 아니라, 플레이어가 다음 수요를 보고 “여기에 더 붙이면 위험하니 다른 회선으로 옮겨야겠다”는 판단을 하게 만드는 것이다. 용어 퀴즈, 정답 배선 따라 그리기, 강제 실패는 성공 지표에서 제외한다.

| 피드백 | 이번 결정 |
| --- | --- |
| 진행 속도 방식은 좋다 | 안정 상태에 반응하는 진행 유지. 미해결·과열·냉각 중 다음 사건 억제 |
| 길이보다 전압·전류 | 케이블 예산, 길이 부족 거절, 길이 성과 지표 제거. 시설의 공급 전압과 회선별 전류 용량을 핵심 제약으로 사용 |
| 맵이 작다 | 실제 조작 대상이 화면의 중심을 차지하도록 카메라·배치·HUD 재설계 |
| 원인을 이해하고 전략을 수정하는 과정이 없다 | 전압 부족 수리 → 부하 증가 → 회선 이동 → 새로운 수요에서 재적용 순서 구성 |
| 전선이 너무 많다 | 고정된 배전 구조, 공급·귀환의 시각적 묶음, 선택 회로 강조로 추적 부담 감소 |
| 삭제도 학습시켜야 한다 | 초반 기존 배선 수리에서 삭제·재연결을 실제 해결 행동으로 사용 |
| 어디서나 분기가 필요한가 | 임의 전선 중간 분기 제거. 분기는 표시된 배전함 접속점으로 한정 |

## 2. 핵심 규칙: 두 회선에 수요를 배분한다

### 길이 제한을 없애도 선택이 남는 구조

현재는 각 시설을 전원에 독립 연결하면 공용 전선의 과부하를 피할 수 있다. 케이블 예산만 없애면 이 해법이 더 유리해진다. 따라서 길이 제한을 삭제하는 작업과 배전 구조 변경을 함께 진행한다.

- 전원에서 **A·B 두 배전 회선**이 나오고, 각 회선은 공급·귀환을 갖춘 배전함으로 이어진다.
- 전원의 내부 연결은 고정 인프라다. 시설은 배전함을 통해 전력을 받는다. 전원에 새 직결선을 계속 추가해 용량을 우회할 수 없다.
- 회선 용량 초안은 각각 0.75 A. 같은 회선에 연결된 시설의 전류가 공용 구간에 모인다. 배전함의 공급·귀환 버스는 서로 전기적으로 분리한다.
- 배전함에는 추가 선을 꽂아도 총 용량이 늘지 않는다. 커넥터 개수나 전선 개수 자체를 별도 자원으로 만들지 않는다.
- 임의 전선 중간과 시설 단자에서 새로운 가지를 생성하지 않는다. 시설 단자는 외부 전선 하나씩을 연결하며, 시설 사이 직렬 연결은 가능하다.
- A와 B를 직접 묶는 연결은 지원하지 않는다. 하나의 부하 경로는 같은 회선의 공급과 귀환을 사용한다. 교차 회선 연결은 승인 전에 이유를 표시하고 거절한다. 이는 퍼즐의 연결 규칙이며, 전기 법칙으로 설명하지 않는다.
- 삭제·다시 연결하기는 무료다. 게임오버나 철거 벌점을 추가하지 않는다.

두 회선과 부하 조합의 타당성은 구현 전 실제 엔진 해법 탐색으로 확인한다. 전구 0.30 A, 펌프 0.45 A를 출발값으로 삼되 합산 표시는 참고값이며 판정에는 실제 계산 전류를 쓴다. 한 회선에 전구 둘과 펌프를 몰면 정격 합계는 1.05 A, 전구와 펌프 한 개씩으로 나누면 각 0.75 A다. 경계값에 지나치게 가까운 해법은 평가 때 전기적 여유까지 확인하여 조정한다.

### 전압과 전류는 다른 현상으로 보인다

| 상태 | 게임에서 보이는 현상 | 플레이어가 바꿀 것 |
| --- | --- | --- |
| 열린 회로 | 해당 시설이 꺼짐, 끊긴 경로 표시 | 공급·귀환 연결 완성 |
| 시설 전압 부족 | 그 시설이 어둡거나 펌프가 약하게 작동, 시설에 전압 부족 표시 | 직렬 연결 등을 해체하고 공급 구조 변경 |
| 회선 과전류 | 해당 배전함과 공용 구간에 전류/용량·열·차단 예고 표시 | 일부 시설을 다른 회선으로 이전하거나 잠시 분리 |
| 회선 차단 | 그 회선의 시설만 꺼짐, 원인 구간과 차단 직전 부하 표시 | 부하를 줄이거나 옮긴 뒤 차단기 복구 |

현재 엔진은 1 V 정규화 모델이고 밝기는 시설 전압의 제곱에 연결된다. 초기에는 이 모델을 유지한다. 화면에서는 공급 충족률을 우선 표시하고 선택 시 실제 전압·전류를 펼친다. 안정 밝기 0.8을 전압 80%와 혼동하지 않는다. 현 모델에서 대응 전압은 약 89.4%다. 전압 부족을 전류계 하나로 설명하거나, 전류가 부족해서 선이 과열된다고 표시하지 않는다.

기존 6초 발열·최대 3초 냉각을 출발점으로 유지한다. 고정 간선은 끊어진 선을 다시 그리게 하는 대신 **회선 차단기**로 복구한다. 이는 새 구현 범위다. 과부하가 지속되면 차단 상태를 유지하며, 부하 재배치와 냉각 후 플레이어가 복구한다. 차단 후 전류가 0이라고 무조건 재투입을 허용하지 않도록, 재투입 시 회로 계산으로 안전 여부를 확인한다. 일반 편집 전선의 기존 발열 동작과 고정 회선 보호 동작을 구별해 검증한다.

## 3. 순차적 전략 경험

아래 다섯 단계는 **한 플레이의 경험 순서**다. 뒤의 5회 구현·평가 루프와 별개다. 시간표로 강제 진행하지 않고 현재 문제 해결과 안정 상태를 확인한다.

| 단계 | 상황 | 플레이어의 판단·행동 | 다음 단계 조건 |
| --- | --- | --- | --- |
| 1. 첫 복구 | A 배전함과 주택 하나 | 공급·귀환을 연결하여 점등 | 안정 점등 확인 |
| 2. 기존 배선 고치기 | 새로 열린 구역에 두 시설이 직렬로 이어진 낡은 배선이 있고 둘 다 어둡다 | 중간 선 선택 → 삭제 → 배전함에서 각각 연결. 기존 연결을 바꿀 수 있음을 경험 | 두 시설 안정. 다른 유효 해법도 인정 |
| 3. 용량의 한계 | 펌프 수요가 예고되고 현재 회선의 여유가 작다. B 회선이 사용 가능하다 | A에 더 붙일지, B로 보낼지, 기존 부하를 옮길지 선택 | 부하 수용 후 두 회선 안전·안정 |
| 4. 수정과 회복 | 다음 수요 변화가 특정 회선의 여유를 압박한다 | 원인 회선을 찾고 시설을 이전. 차단됐으면 재배치 후 복구 | 현재 목표 시설 전체 안정 |
| 5. 판단 재사용 | 시설 위치·부하 조합이 다른 구역 | 이전 배선 복사가 아닌 현재 전류 여유를 보고 배분 | 다른 배분 해법으로도 완료 가능 |

2단계의 낡은 배선은 신규 구역의 초기 상태로 보여 준다. 플레이어가 이미 만든 안전한 배선을 게임이 몰래 바꾸지 않는다. 처음에는 대상 선과 삭제 버튼의 존재만 알려 주며, 재연결의 모든 정답 경로를 동시에 그려 주지 않는다. 잘못 지워도 재연결·실행 취소로 회복할 수 있다. 삭제 사용 자체를 진행 조건으로 삼아 유효한 대체 해법을 막지 않는다.

3·4단계에서 안전하게 배분하거나 사전에 문제를 예방했다면 그대로 통과한다. 반드시 BLACKOUT을 겪어야 하는 미션으로 만들지 않는다. 위험을 방치한 경우에는 실제 계산 결과에 따라 차단된다. 사전에 정전 애니메이션만 예약해 재생하지 않는다.

첫 수요 변화는 연결 구조 선택을, 다음 변화는 기존 연결의 수정을 요구하도록 설계한다. 다만 **모든 안전한 해법을 인위적으로 깨뜨리지 않는다.** 독립 평가에서는 변화에 취약한 배선과 여유를 둔 배선을 모두 재생해 결과 차이를 확인한다.

도움은 지연 시 한 단계씩 제공한다: 문제가 있는 시설/회선 강조 → 해당 전압·전류와 연결된 시설 표시 → 가능한 행동 하나 제안. 정답 배선을 자동 완성하지 않는다. 학습 여부는 용어 설명 대신 다음 수요에서의 선택과 재설계 행동으로 판단한다.

## 4. 맵과 배선 가독성

현재 보드는 전체 화면 크기지만 고정 `1200 × 760` viewBox 안에서 시설이 일부 영역에 모여 있다. SVG 요소의 CSS 크기만 키우는 것으로 해결하지 않고 실제 시설·경로의 범위와 HUD가 차지하는 공간을 기준으로 바꾼다.

- 상단 상태와 하단 도구 영역을 먼저 확보하고 남은 영역을 게임 맵에 배정한다. 여러 안내문을 맵 위에 겹쳐 띄우지 않는다.
- 현재 등장 시설·배전함·주요 경로를 감싸는 카메라로 시작하고 새 구역이 열릴 때만 부드럽게 조정한다. 드래그·선 선택 도중 자동 카메라 이동을 금지한다.
- 가로 화면에서는 조작 대상 범위가 가용 맵 폭의 약 75~90%를 사용하도록 배치한다. 면적 수치를 맞추려고 시설을 잘라내지는 않는다.
- 세로 화면은 별도 배치 또는 확대·이동을 지원한다. 세계 좌표와 전기 연결 상태를 유지하면서 도로 경로를 다시 계산한다. 축소된 가로 지도를 그대로 넣지 않는다.
- 실제 화면 기준 단자 조작 영역 최소 44 CSS px를 목표로 하고 서로 겹치지 않게 한다. 작은 화면은 전체보기와 개별 회로 집중 보기를 오갈 수 있게 한다.
- 공급·귀환은 평상시 나란한 **한 쌍의 경로**로 정돈한다. 전기적으로 두 선을 합치거나 귀환을 자동 생성하지 않는다. 단자 근처와 선택 중에는 두 선을 확실히 구별한다.
- 전선 색만으로 구분하지 않는다. A/B 표식, 선택 윤곽, 방향, 교차점의 비접속 표시를 함께 사용한다. 접속점만 명확한 점으로 표시한다.
- 시설을 선택하면 관련 공급·귀환과 담당 배전함을 강조하고 무관한 선을 흐리게 한다. 위험 회선은 계속 확인할 수 있게 유지한다.
- 삭제 모드에서는 개별 선을 펼쳐 강조하고 양 끝 시설명을 표시한다. 공급·귀환이 겹친 곳은 선택 목록을 제공한다. 어느 선이 삭제되는지 미리 보여 주고 한 번 실행 취소를 지원한다.
- 배전함은 분기 위치가 명백한 유일한 장소다. 일반 전선 드래그로 분기가 시작되지 않게 하여 선택·삭제와 분기 조작이 충돌하지 않게 한다.

전선 수만 줄이는 것은 목표가 아니다. “이 시설은 어디서 전력을 받으며, 어떤 선을 옮겨야 하는가”를 빠르게 찾을 수 있어야 한다.

## 5. 다음 5회 구현·독립 평가 루프

기존 완료 5회와 혼동하지 않도록 새 기록은 `v2-r01`~`v2-r05`로 구별한다. 각 회차는 직전 채택본에서 시작한다. 회차 내 수리·재평가는 새 회차로 세지 않는다.

| 회차 | 구현 묶음 | 독립 평가의 핵심 질문·통과 조건 |
| --- | --- | --- |
| V2-R1. 맵과 추적 | 가용 화면 재배치, 카메라, 회로 선택 강조, 겹친 선 선택·삭제 표시 | 큰 화면과 작은 화면 모두 주요 조작 대상 접근 가능. 드래그 중 카메라 고정. 겹친 선에서 의도한 선만 삭제. 기존 회로 결과 불변 |
| V2-R2. 전기적 제한 | 케이블 예산 제거, A/B 배전 구조, 고정 분기점, 회선 용량·차단·재투입 | 직결·회선 병합으로 용량 우회 불가. 동일 회로의 길이·화면 크기 변경은 전기 결과 불변. 두 가지 이상 유효 배분 존재. 과부하 재투입으로 보호 우회 불가 |
| V2-R3. 삭제와 전압 수리 | 첫 점등 → 낡은 직렬 배선 → 삭제·재연결, 단계별 도움, 실행 취소 | 전압 부족과 열린 회로를 구별해 표시. 삭제·취소 후 그래프·열 상태 일관. 정답 경로 없이 수리 가능. 대체 해법 인정 |
| V2-R4. 수요와 BLACKOUT | 펌프 예고, 회선 전류·연결 시설·차단 원인 연결, 이전·복구 순서 | 수요 증가 → 해당 회선 과열 → 해당 시설 정전의 인과 일치. 다른 회선 유지. 예방과 사후 복구 모두 유효. 복구 중 새 사건 억제 |
| V2-R5. 전략 전이 | 부하 조합이 다른 세 구역, 결과에서 부하 이동 전후 표시, 안내 축소 | 구역별 서로 다른 두 배분 이상 완주. 과거 배선을 그대로 복사하면 위험한 경우와 그대로 안전한 경우 모두 확인. 미공개 평가 조합에서 규칙 일관 |

R2가 채택되지 않으면 R3~R5의 제품 구현을 진행하지 않고 의존 설계를 수정한다. 5회를 채우기 위해 실패한 규칙 위에 기능을 쌓지 않는다. 이번 문서는 실행 계획이며 평가자를 지금 실행시키지는 않는다.

### 평가자와 구현자 분리

- 구현은 현재 작업에서 담당한다. 후보의 최종 판정은 기존 `BLACKOUT · 독립 Evals` 섹션의 별도 평가 작업이 담당한다.
- 평가자는 제품 코드를 수정하지 않는다. 고정 후보의 해시, 독립 시나리오, 실제 입력 증거, 실패 사례, 판정을 남긴다.
- 후보 전달 전 계약에 가설·범위·통과 조건을 고정한다. 전달 후 후보를 동결하며 수정하면 새 해시로 재평가한다.
- 판정은 `ACCEPT_ENGINEERING / REVISE / REJECT`. 사람 플레이 증거는 별도 상태로 남긴다. 이전 기록과 새 규칙용 회귀를 구분하고, 폐기한 케이블 예산 규칙을 새 후보의 통과 조건으로 요구하지 않는다.

### 기계 검증과 실제 전략 학습을 구별한다

필수 자동·브라우저 평가: 전압/전류 계산, 회선별 보호, 열 보존, 삭제·취소, 분기 제한, 무료 재연결, 진행·일시정지·재시작, 화면별 선택 정확성, 두 가지 이상 해법, 불가능한 시나리오·영구 교착 0건. 1280×720·1920×1080·760×550·600×320·390×844를 기본 화면 집합으로 삼는다. 실제 포인터·키보드 입력과 테스트 API 재생을 구별하고 실기기 터치는 수행 여부를 명시한다.

사람 테스트는 신규 플레이어 8명을 초기 탐색 표본으로 제안한다. 아래는 **아직 측정하지 않은 사전 목표**이며 재미 향상의 확증 기준이 아니다.

| 관찰할 행동 | 초기 목표 |
| --- | --- |
| 삭제 발견·사용 | 낡은 배선 문제에서 정답 경로 설명 없이 8명 중 6명 이상이 삭제·재연결로 해결 |
| 회로 추적 | 지정한 시설의 담당 회선과 수정할 선을 10초 안에 찾는 사람이 8명 중 6명 이상 |
| 원인에 맞는 수정 | 과전류 상황에서 무작위 추가 배선 대신 해당 회선의 부하를 줄이거나 옮기는 사람이 노출자의 75% 이상 |
| 다음 상황에 적용 | 배치·부하가 달라진 문제에서 상세 안내 없이 안전하게 예방하거나 수정하는 사람이 8명 중 6명 이상 |
| 선택의 다양성 | 각 고정 구역에 기계적으로 유효한 두 배분 이상. 사람 해법이 한 종류에 집중되면 원인을 검토 |

관찰 단위는 `문제 상태 → 선택한 시설/회선 → 삭제·이전 → 전압/전류 변화 → 복구`다. 단순 삭제 횟수, 실패 횟수, 전류계 클릭 수를 학습으로 계산하지 않는다. 안전하게 예방한 사람도 성공으로 포함한다. 도움 수준과 중단을 기록하고, 재설계 의도는 행동 후 짧게 확인한다. 표본이 없으면 `humanStatus: not_run`으로 남긴다.

기존 로컬 로그에 `scenario_step`, `circuit_selected`, `hint_level`, `wire_remove/undo`, `load_reassigned`, `feeder_trip/reset`과 변경 전후 회선 부하·시설 전압을 보완한다. 이벤트 이름은 구현 전 기존 스키마와 정리한다. 가속 테스트와 사람 세션을 분리한다.

## 6. 구현 경계와 완료 산출물

- `director.js`: 기존 안정 기반 타이밍 유지, 단계별 해결 조건과 사건 예고를 연결.
- `engine.js` 및 새 배전 모델: 고정 회선, 공급·귀환 버스, 용량·보호 상태. 길이와 전기 계산을 분리.
- `game.js`: 임의 분기 제거, 배전함 연결 규칙, 삭제·취소, 회로 선택, 복구 입력.
- `city.js`, `router.js`, `styles.css`, `index.html`: 지도 배치·카메라·선 쌍 표시·HUD. 확대나 경로 재계산이 전기 그래프를 바꾸지 않도록 분리.
- `runs.js`: 시설 종류만 바꾸는 기존 구역에서, 초기 배선·수요 변화·두 가지 이상 해법을 가진 단계 구성으로 확장.
- `cable.js`: 기본 게임의 예산 승인·미터·결과 집계에서 제거. 이전 평가 사본은 보존.
- `telemetry.js`, `evals/`: 원인과 수정의 연결 기록, 새 회차 계약·후보 스냅샷·독립 증거.

최종 산출물은 수정 게임, 새 5회 판정표, 구역별 유효/실패 배선 증거, 실제 입력·화면 검증, 사람 전략 학습의 확인 여부다. **이번 계획의 우선순위는 화면과 연결 구조를 단순화하고, 그 안에서 전기적 한계를 읽고 수정할 이유를 만드는 것**이다.
